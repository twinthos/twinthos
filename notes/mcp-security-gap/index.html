What MCP really is

MCP is an open standard. It is the interface between an AI agent and the world. The agent asks for something. MCP translates that request into a call to a server. The server talks to your email, your calendar, your database, your files.

That makes MCP the bridge between the model and your business. Bridges are useful. They are also choke points. If the bridge is weak, the attacker does not need to break into the model. They break into the bridge.

Most vendors describe MCP as a connector. That is true. What they do not say is that every connector is a potential entry point, and most MCP servers have not been security-reviewed.

The Langflow lesson

Langflow is a visual builder for LangChain workflows. It uses MCP stdio transport to let agents run external tools. In October 2026, CVE-2026-105740 was published. It is an unauthenticated remote code execution flaw in that transport layer.

The CVSS score is 9.9 out of 10. CISA added it to the Known Exploited Vulnerabilities catalog. FIRST EPSS scores it at 0.92, which means a 92% chance of exploitation in the next 30 days. Attackers have already tried it from 27 IPs across 15 countries.

The exploit does not need a password. It does not need the agent to do anything unusual. It just needs the agent to be connected to a vulnerable MCP server. The agent becomes the delivery mechanism.

What to do about it

MCP is not the problem. Unreviewed MCP servers are the problem. Before you connect an agent to any MCP server, check four things.

The fourth check, monitoring, is the one most teams miss. It is not enough to review the server once. You need to know what it is asked to do, and you need to know when it does something new. That requires logging at the MCP layer, not just the application layer.

Most agent platforms do not expose MCP logs. That is a product gap. If your vendor cannot show you the MCP call log, you are trusting their pipeline with your data.

What to checkWhat good looks like
Server provenanceYou know who wrote it, when it was last updated, and whether it has a security policy.
Permission scopeThe server can only access the systems the agent needs, and nothing else.
Transport securitystdio, SSE or HTTP. Each has different risk profiles. stdio is local-only but vulnerable to process injection.
MonitoringYou can see what the server is asked to do, and you can block it if it behaves abnormally.

These checks are not optional. They are the difference between an agent that works and an agent that works until it does not.

What this means for you

If you are evaluating an AI agent platform, ask the vendor about MCP security. Ask who reviews their MCP servers, how often, and what their process is for a critical CVE. If they cannot answer, you are trusting their pipeline with your data.

If you are building your own agent stack, audit every MCP server before you connect it. The Langflow flaw is not unique. It is the shape of things to come.

Questions people actually ask

What is MCP?

Model Context Protocol (MCP) is an open standard that connects AI agents to external tools and data sources. It is the plumbing that lets an agent read your calendar, send emails or query a database.

Is MCP secure?

MCP itself is a protocol. Security depends on implementation. The Langflow CVE-2026-105740 (CVSS 9.9) showed that an unauthenticated MCP stdio transport can allow remote code execution. Always audit MCP server configurations before connecting them to production agents.

Should I stop using MCP?

No. MCP is the best available standard for agent-tool integration. The risk is not the protocol. The risk is connecting to servers you have not reviewed. Audit the server, check the permissions, and monitor what it does.
