The short answer

Before you switch on an AI agent, verify these ten things: permissions, logging, failure mode, data residency, MCP config, prompt injection tests, CISA KEV status, EPSS score, lockfile health, and incident response. Each check takes minutes. Together they take an afternoon. That afternoon is cheaper than the breach you prevent.

The checklist

#CheckWhat good looks like
1PermissionsLeast privilege. The agent can only touch the systems it needs, and nothing else.
2LoggingEvery action is recorded, timestamped and readable by a human.
3Failure modeYou can show what happens when the agent hits an error, and you can stop it.
4Data residencyYou know where the agent's memory lives, and it is in a jurisdiction you trust.
5MCP configEvery MCP server is reviewed, versioned and monitored for drift.
6Prompt injection testsThe agent has been tested against known injection patterns and has a recovery plan.
7CISA KEV statusNo actively exploited CVEs in the agent's stack or dependencies.
8EPSS scoreHigh-probability CVEs (EPSS >= 0.7) are patched or mitigated before go-live.
9Lockfile healthrequirements.txt or equivalent is scanned for known vulnerable versions.
10Incident responseYou have a named person, a runbook, and a tested way to stop the agent.

How to use this

Print the checklist. Walk through it with the vendor or the engineering team. Mark each item as pass, fail or not applicable. The fails are your risk register. The not applicables are your assumptions.

Do this before go-live, not after the first incident. The first incident is when you find out your logs are empty, your permissions are broad, and your incident response plan is a group chat.

The checklist is also useful for vendor evaluation. Send it to every agent vendor you are considering. Their answers tell you more than their demo. A vendor who cannot answer item one, permissions, is telling you they have not thought about security. A vendor who cannot answer item ten, incident response, is telling you they hope nothing goes wrong.

Hope is not a security strategy. A checklist is.

What this means for you

If you are buying an AI agent, ask the vendor to walk through this checklist with you. If they cannot, ask what they check instead. If they cannot answer that, you are buying a demo.

If you are building an agent, run the checklist yourself before it touches production. The ten checks take an afternoon. The breach they prevent takes three months to contain.

Questions people actually ask

How long does the audit take?

The checklist itself takes an afternoon. The Twinthos Operations Audit takes three to five business days, depending on the complexity of the agent stack. The report is delivered as a PDF with findings ranked by severity and a remediation plan.

Do I need technical skills to run the Sentinel?

Basic Python comfort is enough. The Sentinel is a single script with a JSON config file. If you can run python3 ai_sec_sentinel.py --stats, you can run the Sentinel. The output is plain text, and the alerts are sent to Telegram.

What if my agent stack changes?

Re-run the checklist. The ten items are designed to be fast. If you add a new MCP server, check items four and five. If you upgrade the model, check items six and seven. If you change permissions, check item one. The checklist is meant to be iterative, not a one-time event.
