Five questions to ask a managed AI agent provider about data

Before you sign, you should have written answers to these five. They are the same five we answer in writing for every Twinthos setup.

In this guide

1. What can it see, and what does it need to see?

Ask for the exact list of tools and the exact scopes inside each. For a Twinthos setup, this is written down per workflow: which Xero organisations, which HubSpot pipelines, which Gmail labels. The provider should be able to show you the principle of least access, not just "we connect it to your account."

2. Where is the data hosted, and which AI models are used?

Ask for the named providers, the named models, and their training settings. For Twinthos, this includes the cloud region, the inference provider, the model name and version, and whether that provider trains on your data. We publish ours per setup. If a provider cannot, that is the answer.

3. How is your setup kept apart from other clients?

Ask whether the agent runs on shared infrastructure with logical separation, or on a dedicated machine per client. For Twinthos, the default is a dedicated cloud computer per client. Passwords and access are scoped per workflow, rotated on a schedule, and removed on exit. Ask how the provider proves that.

4. What is logged, for how long, and how do you export or delete it?

Ask for the log retention window, the format, and the export mechanism. For Twinthos, every action is logged with timestamp, tool, action, input hash and output, retained for the contract term, and exportable on request in a standard format. Deletion on exit is in the contract.

5. What happens to data, access and records when the service ends?

Ask what the provider does with your credentials, your data, and your logs on termination. For Twinthos, credentials are revoked, exports are issued, logs are retained for the contract term unless you ask for earlier deletion, and a deletion confirmation is issued in writing.

A note on claims

We do not claim that all processing happens in the UK. Where a computer sits does not tell you how every provider in a workflow handles data. If that matters to you, we will write down exactly what each provider in your setup does, in the security answer that ships before anything goes live.
